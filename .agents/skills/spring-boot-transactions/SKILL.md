# 서비스 트랜잭션과 계좌 이체

프로젝트 공통 규칙은 [AGENTS.md](../../../AGENTS.md)를 따른다.

## 구현 절차

1. 함께 커밋/롤백할 작업을 정한다. 예제는 출금 차감과 입금 증가를 하나의 서비스 메서드로 묶는다.
2. 계좌·양수 금액·동일 계좌 정책·잔액 타입·출금 권한을 확인한다. 요청값만으로 권한을 판단하지 않는다.
3. Spring 관리 서비스의 외부 호출 메서드에 @Transactional을 적용한다. 같은 클래스의 직접 호출만으로 프록시 트랜잭션이 시작된다고 가정하지 않는다.
4. 계좌 부재·잔액 부족·영향 행 수 불일치 시 예외를 전파한다. 기본 롤백은 RuntimeException/Error이며 checked exception은 필요 시 rollbackFor를 지정한다.
5. 예외를 잡아 성공처럼 반환하지 않는다. 자원 정리 후 재던지기는 가능하다. HTTP 오류 변환은 컨트롤러/전역 처리기가 맡는다.
6. 동시 변경은 행 잠금 또는 조건부 원자 갱신으로 유실 갱신·초과 출금을 막는다. 여러 행을 잠글 때 순서를 일관되게 정한다.
7. 파일·외부 API는 DB 트랜잭션으로 자동 롤백되지 않으므로 함께 다루면 실패 후 처리 방식을 정한다.

## 검증

정상 이체의 양쪽 잔액·합계, 잔액 부족·0/음수 금액·동시 요청을 검사한다. 출금 후 입금 계좌 없음/두 번째 갱신 실패를 일으켜 별도 조회로 출금 원복을 확인한다. 테스트 자체 롤백만으로 서비스 롤백을 증명하지 않는다.

## 포함된 예제 소스

이 SKILL의 `assets/source/java/`에 Java 예제와 관련 타입을 포함했다. XML·HTML이 필요한 기능에는 `assets/source/resources/`도 포함했다. [포함 파일 목록](references/source-notes.md#포함된-소스)에서 필요한 파일만 읽는다. 외부 back-end-spring-boot 프로젝트 경로를 찾을 필요가 없다. 원본 사본이므로 아래 참고 문서의 차이점과 이 SKILL의 구현 지침에 맞춰 적용하며, 그대로 실행 가능한 현재 프로젝트 코드로 간주하지 않는다.
